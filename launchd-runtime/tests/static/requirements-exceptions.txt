# Repos in ACTIVE_REPOS whose host tooling is declared nowhere.
#
# test_requirements_manifests.sh fails the suite for an active repo that has
# no manifest in its own checkout, no staged
# `launchd-runtime/requirements-templates/<owner>-<repo>.conf`, and no line
# here. That is the whole mechanism: a repo may go undeclared, but not
# silently.
#
# A repo covered by a staged template is DECLARED, because check-requirements
# falls back to that template and evaluates it. Listing such a repo here is a
# stale exception, and the same test rejects one: an exception that no longer
# applies reads as policy and hides the coverage that replaced it.
#
# One `owner/repo` per line, followed by ` # ` and the REASON it has none.
# The reason is enforced — an undocumented exception is the thing this file
# exists to prevent. Delete a line the moment that repo is covered.
#
# A manifest is never invented. "Nothing has failed on this host for want of
# tooling" is a legitimate reason to have none; guessing at requirements
# produces a checker that fails on things the project does not actually need,
# which is how a gate teaches its reader to skip it.
